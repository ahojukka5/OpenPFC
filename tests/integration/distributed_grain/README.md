# Distributed grain transaction verification

The fixture uses independent complete global labels on a tiny domain as an
oracle. Production APIs exchange compact components, boundary samples and
contacts; neither amplitudes nor dense ownership volumes are MPI-gathered.
Six-connectivity cases cross faces and periodic x seams. Twenty-six cases
cross decomposition edges/corners and periodic corners. Partial CPU seeds
are reconciled through same-slot component unions. Native HIP uses complete
known-UID labels and device contact detection; it does not invent grain births.

Each checked call produces one global graph and coloring using the existing
bounded policies. A contact triangle forces a real slot change and rejects
a two-slot palette. Transfers preserve UID and every finite signed amplitude
exactly, including negative and UID-owned zero values. One-rank failure and
inconsistent-plan controls reject before any caller publication. The native
fixture requires real hardware and uses a nonblocking stream. Complete local
host reads in the fixture are correctness audits, not a production output path.

Supported ownership is a disjoint Cartesian tiling of the global box. Whole
locally owned periodic axes wrap locally; split periodic axes reconcile via
boundary summaries. All ranks call collectives in the same order. Use the
producer overload of `prepare` so a local producer exception is voted before
the next collective. `stage` callbacks must stage owning results without
mutating originals. Only after collective Success may the caller replace
values/labels and publish the global registry together. MPI process loss is
outside the rollback contract.

For signed physical fields, labels explicitly define the entire influencing
support independently of amplitude sign. Background UID zero requires the
exact declared background value; UID-owned samples may carry any finite value.
There is no clipping, cutoff or projection in transfer. Full diffuse supports
that overlap everywhere require enough slots for every grain. A limited palette
requires application-owned, explicitly justified support semantics and a
contact buffer covering its numerical stencil. Remapping cannot repair amplitudes
already mixed by same-slot touching grains; ambiguous unions reject.

Storage is explicit: original and staged double values plus uint64 UID labels
require 32 bytes per sample per slot, excluding evolution, halos and tracking
scratch. At 1024x512x512 over eight equal ranks and four slots this alone is
4 GiB per rank. Shell extraction is bounded by its geometrical surface/width
and an explicit sample capacity. Gathered summary words have an explicit
capacity; exhaustion rejects collectively. This compact all-gather realization
replicates shells on each host and is not a distributed-volume scalability
claim. Device adjacency also retains its existing O(grains squared) metadata
limit. GPU fields remain resident through graph/transaction operations; only
shells, counts, edges and validation flags return to the host.

Run canonical `scripts/build.sh --machine=lumi --cpu --no-heffte --mpi-tests`
first, then the HIP configuration. Direct and 1/2/4/8-rank CTest entries are
registered. No physical-model, timing, CUDA or production-size claim follows
from these small correctness controls.

The explicit `observe_bounds` / `prepare_bounds` path instead reduces complete
known-UID support to seven integers per grain on the device. It combines
local bounds globally before forming buffered contacts, including periodic
minimum distances. Its graph is a conservative superset, verified against the
independent exact contact oracle; disconnected islands may add false contacts
and force a larger palette or rejection. Same-slot bound distance at most one
rejects conservatively as unsafe. Bounds do not invent births or repair mixed
support. Use a pre-stage buffer covering both UID influence horizons, such as
at least six for radius-three FD6 expansion, and include every actual operator
that expands phase support. This O(grains)-metadata alternative avoids dense
shell extraction and radius-stencil graph scans. It changes contact semantics
explicitly and provides no production-size timing or fit claim.

Unknown coloring policies and non-null diagnostics requests reject explicitly;
this coordinator does not implement the local remapper's diagnostic counters.
The common options' local `max_sweeps` is not a limit on component union or
support-box reduction; those producers are non-iterative collective operations.
