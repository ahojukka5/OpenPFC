# Checkpoint field and verification-hold replay

Job 22181773 (`project_462001245`, one node/eight GCDs) compares uninterrupted
and stop/resume runs using the existing `--stop-after` boundary. No process
failure or file-write fault is injected by this test.

- Homogeneous control: stop after 50 evaluated states, with quiet count 49
  and 71 verification states remaining. Restart preserves the original
  20 + 100 contract and converges at accepted state 120, exactly matching the
  uninterrupted run. All 123 field files and all 71 overlapping CSV rows
  (excluding elapsed time) match exactly.
- Moving noisy control: stop after four states and resume through accepted
  state eight (`MAX_STEPS`, not convergence). All 11 fields, five overlapping
  rows and the complete terminal checkpoint metadata match exactly. Final
  design RMS is 0.00110876, so this is not a constant-field-only comparison.
- Terminal checkpoints are rejected in both cases; the saved bundle remains
  unchanged. Both full and thresholded fields are included in the comparisons.

`verified.json` records every field hash, interrupted tracker state, terminal
row and overlap count. `raw.json.gz` preserves commands, CSVs, logs, metadata
and the target. Field bricks are regenerated by the replay driver; these tiny
fixtures use the pinned binary defaults and the recorded module environment.
`provenance.json` identifies the executable source, binary and target hashes.

Build through `scripts/build.sh --machine=lumi --with-rocm` with account
`project_462001245`. In a one-node/eight-GCD allocation with that module stack:

```sh
python3.11 apps/inverse_homogenization/scripts/replay_checkpoint_state.py \
  --binary /path/to/openpfc_inverse_homogenize_hip \
  --target /path/to/target.txt --output /new/scratch/output --ranks 8
```

This result verifies actual fields and hold restoration. It does not qualify
atomic publication, failed writes, damaged snapshot metadata, every change of
run budget, or production walltime recovery. Full build jobs 22181643/22181690
pass the new tests and 138/139 batches but reproduce the parent branch's known
finite-strain failure (#76); that already-fixed dependency must be integrated
before claiming an all-green checkpoint executable.
